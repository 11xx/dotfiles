#+subtitle: Wayland screenshot helper with immediate notification and lossless JPEG XL output

This helper is intentionally simpler than the earlier dual-output version. It
captures one screenshot and writes one final file: a mathematically lossless
JPEG XL image.

The important workflow detail is that the user-facing notification is not tied
to the slow encoder step. The capture is made first, a small PNG thumbnail is
created immediately, and the desktop notification is sent before =cjxl= starts
its heavier lossless compression work.

The source blocks under this heading tangle, in order, into
=~/.local/bin/screenshot-jxl=. Example blocks use =:tangle no= so they remain
part of the document without becoming part of the script.

** Dependencies

The script is Wayland-native and is intended for Hyprland or another compositor
that works with =grim=.

#+begin_src bash :tangle no
sudo pacman -S grim slurp libjxl wl-clipboard libnotify imagemagick xdg-user-dirs jq
#+end_src

The relevant commands are:

- =grim= for Wayland screenshot capture;
- =slurp= for region selection;
- =cjxl= for JPEG XL encoding;
- =wl-copy= for Wayland clipboard support;
- =notify-send= for desktop notifications;
- =magick= for the fast PNG thumbnail and optional PNG clipboard image;
- =hyprctl= (ships with Hyprland) and =jq= for =--window= selection;
- =xdg-user-dir= for the default Pictures directory, when available.

The script can still fall back to =$HOME/Pictures= if =xdg-user-dir= is absent
or fails.

** Format policy

Screenshots are archival by default. Flat UI colors, text, terminals, icons,
subpixel rendering, and theme previews are all hostile to lossy compression when
exact visual structure matters.

The final file is therefore encoded as JPEG XL with distance =0=:

#+begin_src bash :tangle no
cjxl input.ppm output.jxl --distance 0 --effort 9
#+end_src

That preserves exact pixels while allowing JPEG XL to compress the image more
aggressively than a normal PNG workflow often would.

The tradeoff is that high-effort lossless JXL encoding can take noticeably
longer than simply writing a PNG. To keep the interaction responsive, the script
sends its screenshot notification immediately after capture and thumbnail
creation, then performs the final encode afterward.

** Script prelude

Use Bash rather than POSIX =sh= because arrays make the =grim= argument list and
notification body construction safer and simpler.

#+begin_src bash
set -Eeuo pipefail
#+end_src

** Defaults

The default mode is fullscreen capture.

The default output is a single lossless JPEG XL file under
=~/Pictures/screenshots/=. The default encoder effort is =9= because the slow
part now happens after the immediate notification. Lower it with =--effort= if
latency or CPU use matters more than file size. Effort accepts =1..10=, where
=10= is the slowest and produces the smallest file.

Encoding is mathematically lossless by default (=jxl_distance= is =0=). Pass
=--lossy= for a smaller =--distance 2.0= encode when exact pixels are not
required; =--lossless= is the explicit spelling of the default.

The default clipboard behavior is =path=: the final output path is copied as
soon as the path is known. The file may still be encoding for a short period
after the notification appears.

#+begin_src bash
app_name="Screenshot"

mode="fullscreen"
include_cursor=0

copy_mode="path"
notify_enabled=1
verbose=0

jxl_effort=9
jxl_distance=0
output_dir=""
#+end_src

** Diagnostics

Failures should be visible even when the script is called from a Hyprland
binding. =die= prints to stderr and also uses =notify-send= when notification is
enabled and the command exists.

#+begin_src bash
notify_error() {
    [[ "$notify_enabled" -eq 1 ]] || return 0
    command -v notify-send >/dev/null 2>&1 || return 0

    notify-send --urgency=low --app-name="$app_name" \
        "Screenshot failed" \
        "$1"
}

die() {
    notify_error "$1" || true
    printf 'screenshot-jxl: %s\n' "$1" >&2
    exit 1
}
#+end_src

Dependency checks are explicit. Optional commands are only required when their
corresponding feature is active.

#+begin_src bash
need() {
    command -v "$1" >/dev/null 2>&1 || die "missing dependency: $1"
}
#+end_src

#+begin_src bash
check_effort() {
    case "$1" in
        [1-9]|10) ;;

    esac
}

** Argument parsing

Each option mutates one script variable and shifts its own arguments. There are
no positional arguments because the screenshot source is always the compositor.

#+begin_src bash
while [[ $# -gt 0 ]]; do
    case "$1" in
        -s|--select)
            mode="region"
            shift
            ;;
        -w|--window)
            mode="window"
            shift
            ;;
        -f|--fullscreen)
            mode="fullscreen"
            shift
            ;;
        -c|--cursor)
            include_cursor=1
            shift
            ;;
        --effort)
            [[ $# -ge 2 ]] || die "--effort requires a value"
            jxl_effort="$2"
            shift 2
            ;;
        --lossy)
            jxl_distance=2.0
            shift
            ;;
        --lossless)
            jxl_distance=0
            shift
            ;;
        --output-dir|--screenshots-dir)
            [[ $# -ge 2 ]] || die "$1 requires a directory"
            output_dir="$2"
            shift 2
            ;;
        --copy)
            [[ $# -ge 2 ]] || die "--copy requires: path, image, or none"
            case "$2" in
                path|image|none)
                    copy_mode="$2"
                    ;;
                *)
                    die "invalid --copy mode: $2"
                    ;;
            esac
            shift 2
            ;;
        --no-notify)
            notify_enabled=0
            shift
            ;;
        -v|--verbose)
            verbose=1
            set -x
            shift
            ;;
        -h|--help)
            usage
            exit 0
            ;;
        --)
            shift
            break
            ;;
        -* )
            die "unknown option: $1"
            ;;
        *)
            die "unexpected positional argument: $1"
            ;;
    esac
done
#+end_src

** Output directory

Use the XDG Pictures directory when possible. Falling back to =$HOME/Pictures=
keeps the script usable in smaller shells or stripped-down environments.

#+begin_src bash
get_pictures_dir() {
    if command -v xdg-user-dir >/dev/null 2>&1; then
        xdg-user-dir PICTURES 2>/dev/null || printf '%s/Pictures\n' "$HOME"
    else
        printf '%s/Pictures\n' "$HOME"
    fi
}
#+end_src

If no output directory was provided, screenshots go under
=Pictures/screenshots=.

#+begin_src bash
pictures_dir="$(get_pictures_dir)"

if [[ -z "$output_dir" ]]; then
    output_dir="$pictures_dir/screenshots"
fi

mkdir -p "$output_dir"
#+end_src

Notification thumbnails are placed under the cache directory instead of the
runtime temporary directory. Some notification daemons load icon files after the
script has already moved on; a cache path avoids racing against cleanup.

#+begin_src bash
cache_dir="${XDG_CACHE_HOME:-$HOME/.cache}/screenshot-jxl"

#+end_src

** File names

The timestamp is recorded before capture so the name reflects when the shortcut
was pressed, not when compression finished.

#+begin_src bash
timestamp="$(date +'%Y%m%d-%H%M%S')"
base_name="${timestamp}-screenshot"

output_file="$output_dir/${base_name}.jxl"
thumb_file="$cache_dir/${base_name}-thumb.png"
#+end_src

** Temporary capture state

The compositor capture is written to a temporary PPM file. PPM is intentionally
used as a simple lossless intermediate: it is fast, unambiguous, and accepted by
both ImageMagick and =cjxl=.

#+begin_src bash
tmpdir="$(mktemp -d "${TMPDIR:-/tmp}/screenshot-jxl.XXXXXXXX")"
trap 'rm -rf "$tmpdir"' EXIT

tmp_ppm="$tmpdir/capture.ppm"
#+end_src

** Capture arguments

The =grim= command is built as an array to avoid quoting bugs. Cursor capture is
added only when requested.

#+begin_src bash
grim_args=(-t ppm)

if [[ "$include_cursor" -eq 1 ]]; then
    grim_args+=(-c)
fi
#+end_src

For region screenshots, =slurp= returns the geometry string. An empty result
means the selection was cancelled.

For window screenshots, the geometries of every window on the currently visible
workspaces are piped to =slurp -r=, which restricts the selection to those
boxes; a single click then picks one window. Off-screen windows are excluded by
keeping only clients whose workspace is active on some monitor, so only windows
you can actually see are offered. This is a self-contained equivalent of the
=hyprprop | grim= recipe, built from =hyprctl= and =jq= directly. The trailing
=\(.class)= is a slurp label and is dropped from slurp's default geometry
output, so =grim= still receives a clean =x,y WxH= string.

#+begin_src bash
if [[ "$mode" = "region" ]]; then
    geometry="$(slurp || true)"
    [[ -n "${geometry:-}" ]] || die "selection cancelled"
    grim_args+=(-g "$geometry")
elif [[ "$mode" = "window" ]]; then
    visible_ws="$(hyprctl -j monitors \
        | jq -c '[.[] | .activeWorkspace.id, .specialWorkspace.id]')" \
        || die "could not query Hyprland monitors"

    window_boxes="$(hyprctl -j clients \
        | jq -r --argjson vis "$visible_ws" '
            .[]
            | select(.mapped and (.hidden | not))
            | select(.workspace.id as $id | ($vis | index($id)) != null)
            | "\(.at[0]),\(.at[1]) \(.size[0])x\(.size[1]) \(.class)"')" \
        || die "could not query Hyprland windows"

    [[ -n "$window_boxes" ]] || die "no on-screen windows to select"

    geometry="$(printf '%s\n' "$window_boxes" | slurp -r || true)"
    [[ -n "${geometry:-}" ]] || die "selection cancelled"
    grim_args+=(-g "$geometry")
fi
#+end_src

** Capture execution

The screenshot is captured once. Everything else works from this temporary
lossless source.

#+begin_src bash
grim "${grim_args[@]}" "$tmp_ppm" || die "grim failed"

[[ -s "$tmp_ppm" ]] || die "capture was not created"
#+end_src

** Immediate thumbnail

The thumbnail is generated before any final JPEG XL encoding. It is small and
uses low PNG compression because the point is responsiveness, not archival
quality.

#+begin_src bash
make_thumbnail() {
    magick "$tmp_ppm" \
        -thumbnail '300x300>' \
        -strip \
        -define png:compression-level=0 \
        "$thumb_file" \
        >/dev/null 2>&1 || true
}
#+end_src

Create the thumbnail immediately after capture.

make_thumbnail

** Immediate notification

This notification is intentionally sent before =cjxl= runs. It means “the
screen has been captured successfully and final encoding is now in progress”.
If encoding later fails, a separate error notification is sent by =die=.

#+begin_src bash
notify_captured() {
    [[ "$notify_enabled" -eq 1 ]] || return 0

    local title
    case "$mode" in
        region) title="Region screenshot captured" ;;
        window) title="Window screenshot captured" ;;
        *)      title="Fullscreen screenshot captured" ;;
    esac

    local kind
    if [[ "$jxl_distance" = "0" ]]; then
        kind="lossless"
    else
        kind="lossy"
    fi

    local body
    body="Encoding $kind JPEG XL: $output_file"

    case "$copy_mode" in
        path)  body+=$'\nClipboard: copying output path' ;;
        image) body+=$'\nClipboard: preparing PNG image data' ;;
        none)  body+=$'\nClipboard: unchanged' ;;
    esac

    if [[ -f "$thumb_file" ]]; then
        notify-send --urgency=normal --app-name="$app_name" \
            --icon="$thumb_file" \
            "$title" \
            "$body"
    else
        notify-send --urgency=normal --app-name="$app_name" \
            "$title" \
            "$body"
    fi
}
#+end_src

Send the notification before clipboard conversion and before final compression.

#+begin_src bash
notify_captured
#+end_src

** Clipboard writing

Path clipboard mode can happen immediately because the output path is already
known. The file may still be encoding when the path is copied.

PNG image clipboard mode is provided for applications that cannot paste JPEG XL.
It is performed before the final encode so the screenshot can be pasted without
waiting for =cjxl=.

#+begin_src bash
case "$copy_mode" in
    path)
        printf '%s' "$output_file" | wl-copy
        ;;
    image)
        magick "$tmp_ppm" png:- | wl-copy --type image/png || \
            die "failed to copy PNG image to clipboard"
        ;;
    none)
        ;;
esac
#+end_src

** JPEG XL encoding

The final file is encoded after the notification and clipboard work. The
=--distance= value comes from =jxl_distance=: =0= is mathematically lossless
(the default), while =--lossy= sets =2.0=.

#+begin_src bash
encode_jxl() {
    cjxl "$tmp_ppm" "$output_file" \
        --distance "$jxl_distance" \
        --effort "$jxl_effort" \
        >/dev/null || die "cjxl encode failed"

    [[ -s "$output_file" ]] || die "JXL output was not created"
}
#+end_src

Run the encoder as the final expensive operation.

#+begin_src bash
encode_jxl
#+end_src

* tofimoji: Minimal emoji picker with tofi
:PROPERTIES:
:header-args:shell: :tangle tofimoji :shebang #!/usr/bin/env sh
:END:
# [2023-06-14 Wed 15:45:50 -03]
# [2026-01-15 Thu 16:56:00 -03] @ak updated tofi config
# [2026-03-25 Wed 13:52:53 -03] @ak added custom emojis.txt
# [2026-07-05 Sun 15:37:12 -03] @ak moved to .local/bin/README

- DEPENDENCIES
  + =tofi=: fast wayland dmenu-like program
  + =noto-fonts-emoji=: Display all emojis preview correctly
  + =wl-clipboard=: Wayland clipboard
  + =curl= or =wget=: first-run emoji index download
  + =notify-send=: optional desktop error reporting
  + =emojis.txt= from the =emoji-index= repo

*NOTE*: the =--font= argument should point to a relative font name and not
a full path because =tofi= also searches for alternative characters on
fonts other than the one specified by name.

This started from =whoisYoges/emojimenu=. The local version reads the generated
emoji index, lets =tofi= filter the full searchable line, and copies only the
first field from a confirmed selection. Canceling the picker should leave the
clipboard alone. =TOFIMOJI_EMOJIS= and =TOFIMOJI_CONFIG= can override the
defaults for testing or alternate indexes. On first run, it downloads
=emojis.txt= into =${XDG_DATA_HOME:-~/.local/share}/tofimoji/= if the file is
not already present.

#+begin_src shell
set -eu

font_name='Liberation Sans'
data_home=${XDG_DATA_HOME:-${HOME}/.local/share}
emoji_file=${TOFIMOJI_EMOJIS:-${data_home}/tofimoji/emojis.txt}
emoji_url=${TOFIMOJI_EMOJIS_URL:-https://codeberg.org/useless-utils/emoji-index/raw/branch/master/emojis.txt}
xdg_config_home=${XDG_CONFIG_HOME:-${HOME}/.config}
tofi_config=${TOFIMOJI_CONFIG:-${xdg_config_home}/tofi/tofimoji}

notify_error() {
    message=$1
    if command -v notify-send >/dev/null 2>&1; then
        notify-send "tofimoji" "$message"
    fi
    printf '%s\n' "tofimoji: $message" >&2
}

require_cmd() {
    if ! command -v "$1" >/dev/null 2>&1; then
        notify_error "missing required command: $1"
        exit 127
    fi
}

require_cmd tofi
require_cmd wl-copy

download_emojis() {
    emoji_dir=${emoji_file%/*}
    if [ "$emoji_dir" = "$emoji_file" ]; then
        emoji_dir=.
    fi

    if ! mkdir -p "$emoji_dir"; then
        notify_error "cannot create emoji data directory: $emoji_dir"
        exit 1
    fi

    download_tmp=${emoji_file}.$$.tmp
    trap 'rm -f "$download_tmp"' HUP INT TERM EXIT

    if command -v curl >/dev/null 2>&1; then
        if ! curl -fsSL "$emoji_url" -o "$download_tmp"; then
            notify_error "failed to download emoji index"
            exit 1
        fi
    elif command -v wget >/dev/null 2>&1; then
        if ! wget -qO "$download_tmp" "$emoji_url"; then
            notify_error "failed to download emoji index"
            exit 1
        fi
    else
        notify_error "missing required command: curl or wget"
        exit 127
    fi

    if [ ! -s "$download_tmp" ]; then
        notify_error "downloaded emoji index is empty"
        exit 1
    fi

    if ! mv "$download_tmp" "$emoji_file"; then
        notify_error "cannot install emoji index: $emoji_file"
        exit 1
    fi

    trap - HUP INT TERM EXIT
}

if [ ! -s "$emoji_file" ]; then
    download_emojis
fi

if [ ! -r "$emoji_file" ]; then
    notify_error "emoji index not readable: $emoji_file"
    exit 1
fi

if [ ! -r "$tofi_config" ]; then
    tofi_config=${xdg_config_home}/tofi/center-box
fi

if [ ! -r "$tofi_config" ]; then
    notify_error "tofi config not readable: $tofi_config"
    exit 1
fi

selection=$(tofi --font="$font_name" -c "$tofi_config" < "$emoji_file") || exit 0
[ -n "$selection" ] || exit 0

emoji=${selection%% | *}
[ -n "$emoji" ] || exit 0

printf '%s' "$emoji" | wl-copy
#+end_src

* darkman-disable
:PROPERTIES:
:header-args:bash: :tangle darkman-disable :shebang "#!/usr/bin/env bash"
:END:

Toggle Darkman as a whole, rather than merely stopping it.  The service is
D-Bus activatable, so the off state is both disabled and masked; the on state
unmasks it before enabling it again.

Darkman runs the legacy scripts in its systemd cgroup.  Stopping the service
therefore also stops the long-running =swaybg= started by =wallpaper.sh=.  On
the off transition this helper determines the current mode before stopping
Darkman, then invokes that mode's wallpaper script directly after the service
has stopped.  The replacement =swaybg= is outside Darkman's cgroup and keeps
the current wallpaper in place while switching is disabled.

#+begin_src bash
set -Eeuo pipefail

unit=darkman.service
config_home=${XDG_CONFIG_HOME:-"${HOME}/.config"}
data_home=${XDG_DATA_HOME:-"${HOME}/.local/share"}

current_mode() {
    local mode target

    mode=$(darkman get 2>/dev/null || true)
    case "$mode" in
        dark|light)
            printf '%s\n' "$mode"
            return
            ;;
    esac

    target=$(readlink -f "${config_home}/hypr/themes/active-theme.lua" 2>/dev/null || true)
    case "$target" in
        *.dark) printf '%s\n' dark ;;
        *.light) printf '%s\n' light ;;
        *)
            printf '%s\n' 'darkman-disable: cannot determine the current mode' >&2
            return 1
            ;;
    esac
}

disable_darkman() {
    local mode wallpaper_script wayland_display service_environment entry

    mode=$(current_mode)
    wallpaper_script="${data_home}/${mode}-mode.d/wallpaper.sh"
    wayland_display=${WAYLAND_DISPLAY:-}
    if [ -z "$wayland_display" ]; then
        service_environment=$(systemctl --user show --value --property=Environment "$unit")
        for entry in $service_environment; do
            case "$entry" in
                WAYLAND_DISPLAY=*)
                    wayland_display=${entry#WAYLAND_DISPLAY=}
                    break
                    ;;
            esac
        done
    fi

    systemctl --user disable --now "$unit"
    systemctl --user mask "$unit"

    if systemctl --user is-active --quiet "$unit"; then
        printf '%s\n' 'darkman-disable: Darkman did not stop' >&2
        return 1
    fi
    if [ ! -x "$wallpaper_script" ]; then
        printf 'darkman-disable: missing wallpaper script: %s\n' "$wallpaper_script" >&2
        return 1
    fi

    XDG_CONFIG_HOME="$config_home" XDG_DATA_HOME="$data_home" \
        WAYLAND_DISPLAY="$wayland_display" "$wallpaper_script"
    printf 'Darkman disabled; retained %s wallpaper.\n' "$mode"
}

enable_darkman() {
    systemctl --user unmask "$unit"
    systemctl --user enable --now "$unit"
    printf '%s\n' 'Darkman enabled.'
}

if systemctl --user is-enabled --quiet "$unit"; then
    disable_darkman

* launch: Open files by extension and MIME type
:PROPERTIES:
:header-args:shell: :tangle launch :shebang #!/usr/bin/env sh
:END:
# [2026-07-26 Sun] @ak moved to .local/bin/README

=launch= is the opener that =xdg-open= delegates to. It picks a program for
each file, and for the programs that render into a terminal it also picks the
window geometry, which is the part a plain MIME association cannot express.

Dispatch happens in two passes. The first matches the lowercased file
extension, so that formats sharing a MIME type can still reach different
programs. Anything the extension pass does not claim falls through to a second
pass over the MIME type reported by =file=, which ends in a catch-all that
reports the unmatched extension and MIME type instead of failing silently.

Every handler ends with =exit 0=, because both =case= statements run in
sequence; a handler that returned normally would be re-dispatched by the MIME
pass.

- DEPENDENCIES
  + =file=: MIME type detection
  + =bat=: text rendering
  + [[#terminal][=terminal=]]: floating terminal windows for text output
  + [[#image-viewer][=image-viewer=]]: image display
  + =mpv=, =zathura=, =inkview=, =firefox=, =dolphin=: viewers
  + =bsdtar=, =7z=: archive listings
  + =notify-send=: failure reporting

** Window placement

Floating is requested by embedding the string =FLOAT_WMRULE= in the window
title or class. The compositor matches it and floats the window, which lets
=launch= mark a window without the compositor needing a rule per program. The
Hyprland side of the contract lives in =window-rules.lua=:

#+begin_src lua :tangle no
window_rule({ title = "^.*(floatWMRULE|FLOAT_WMRULE)$" },
            { float = true, size = { "70%", "70%" } })
window_rule({ class = "^.*(floatWMRULE|FLOAT_WMRULE)$" }, { float = true })
#+end_src

The two rules differ deliberately. Programs marked by *title* are media
viewers with no useful size of their own, so the compositor gives them one.
Programs marked by *class* are terminals launched by [[#terminal][=terminal=]], which have
already been given an exact column and row count, so a size rule there would
overwrite the measurement it just made.

Both sites have to agree on the literal string; changing it in one place alone
silently stops the floating.

** Text handler

The window is sized to the content. =bat= is measured against the longest of
the first 500 lines: narrow files get the default 120 columns, wider ones grow
to fit, and anything past the maximum is capped so the window still fits on
screen. The height for the middle case is derived from the width, which keeps
wide-and-short output from opening a tall, mostly empty window.

=--style= differs between one file and several, because the grid separators
are what makes a multi-file listing readable.

#+begin_src shell
text() {
    while :; do
        case "$1" in
            (-l)
                [ -n "$2" ] || {
                    printf 'ERROR: "%s" cannot be empty.\n' "$1" >&2; exit 1; }
                case "$2" in
                    (json) usingTmp=t; isJq=t; batLang="-l json" ;;
                    (pts|picard) batLang="-l pts" ;;
                esac
                shift
                ;;
            (-s|--style)
                [ -n "$2" ] || {
                    printf 'ERROR: "%s" cannot be empty.\n' "$1" >&2; exit 1; }
                case "$2" in
                    (h|header) batStyle=header ;;
                    (g|grid) batStyle=grid ;;
                    (hg|header-grid) batStyle=header,grid ;;
                    (*) batStyle="$2" ;;
                esac
                shift
                ;;
            (*) break
        esac
        shift
    done

    maxTermCols=220
    maxTermLines=60
    defTermCols=120
    defTermLines=30

    if [ "$usingTmp" = t ]; then
        make_tmp
        [ "$isJq" = t ] && jq '.' "$@" > "$tmp"
        set -- "$tmp"
    fi

    len=$(head -500 "$@" | wc -L)

    batPagingOpt=--paging=${scriptMode:+never}
    batPagingOpt=${scriptMode:+$batPagingOpt}
    batPagingOpt=${batPagingOpt:---paging=always}

    if [ "$#" -gt 1 ]; then
        batCmd="bat $batLang --style=${batStyle:-header,grid} $batPagingOpt"
    else
        batCmd="bat $batLang --style=${batStyle:-header} $batPagingOpt"
    fi

    if [ -n "$scriptMode" ] || [ -n "$noWindow" ]; then
        $batCmd "$@"
        exit 0
    fi

    if [ "$len" -lt $((defTermCols - 1)) ]; then
        termW=$defTermCols; termH=$defTermLines
    elif [ "$len" -lt $((maxTermCols - 1)) ]; then
        termW=$((len + 1)); termH=$((len / 4))
    else
        termW=$maxTermCols; termH=$maxTermLines
    fi

    terminal --float -w "$termW" -h "$termH" "$batCmd" "$@"
    exit 0
}
#+end_src

** Archive handler

Archives are listed, never extracted; extraction is =xtodir='s job. Several
archives are concatenated into one buffer separated by a rule as wide as the
widest line, so the result reads as a single grid rather than as unrelated
listings.

Listing goes through =bsdtar= first, since libarchive reads tar, zip, 7z, rar,
iso and cpio through one interface. =7z= covers the remainder, and a failure of
both is reported per file rather than aborting the whole listing.

#+begin_src shell
list_archive() {
    bsdtar --list --file "$1" 2>/dev/null ||
        7z l -- "$1" 2>/dev/null ||
        printf 'Cannot list this archive.\n'
}

archive() {
    make_tmp
    if [ "$#" -gt 1 ]; then
        for file in "$@"; do
            printf 'File: %s\n%s\nGRIDMARKER\n\n' \
                   "$file" "$(list_archive "$file")"
        done > "$tmp"
        wcL=$(head -500 "$tmp" | wc -L)
        sed -i "s/GRIDMARKER/$(repeat_char "─" "$wcL")/g" "$tmp"
        text --style grid "$tmp"
    else
        list_archive "$1" > "$tmp"
        text --style plain "$tmp"
    fi
}
#+end_src

* image-viewer: Open images in the selected viewer
:PROPERTIES:
:CUSTOM_ID: image-viewer
:header-args:shell: :tangle image-viewer :shebang #!/usr/bin/env sh
:END:

A single entry point for displaying images, so that swapping viewers is one
command rather than an edit to [[#launch][=launch=]]. The choice persists in
=$XDG_STATE_HOME/image-viewer= and =--toggle= flips it.

=qimgv= is the default. It decodes through a parallel-capable Qt plugin and
preloads neighbouring files, which is what makes stepping through a folder feel
immediate. It needs the =kimageformats= package for JPEG XL, AVIF and HEIF.

=qimgv= is started under XWayland. Its native Wayland backend scales
fit-to-window by half, leaving the image at a quarter of its correct area in
the middle of the window; the same image under =xcb= fills the window exactly.
A default configuration reproduces the fault and enabling OpenGL does not
change it, so the platform override is the fix itself rather than a workaround
for local settings. The cost is that XWayland does not do fractional scaling,
so qimgv is slightly soft on an output whose scale is not 1.

=imv= is the alternative: Wayland-native, decoding JPEG XL through =libjxl=
with no optional plugin, and setting its own =app_id= so the compositor can
float it by class rather than by a marker smuggled through the window title.

Its weakness is speed on large files. It gives =libjxl= no parallel runner and
does not preload the next image, so a 10-megapixel screenshot costs roughly two
seconds against a quarter of that decoded in parallel, and holding a navigation
key pins a core. Neither behaviour is configurable, which makes it the wrong
choice for folders of large images and a fine one for ordinary photographs.

*** qimgv settings this relies on

qimgv rewrites its own configuration when it exits, so the file is owned by the
program rather than tangled from here. These are the values to restore if it is
ever reset, in =$XDG_CONFIG_HOME/qimgv/qimgv.conf=:

#+begin_src conf :tangle no
useSystemColorScheme=false
infoBarWindowed=true
infoBarFullscreen=true
#+end_src

=useSystemColorScheme= must be off. Left on, qimgv takes the Qt palette and
renders the thumbnail panel on a white background and the info bar as dark text
on a dark background, which makes the bar invisible in fullscreen. Turning it
off makes qimgv use its own =bgColor=, =bgColorFullscreen= and
=fullscreenInfoTextColor= values, which are already set to a dark theme.

The cursor comes from a third place again. Under XWayland with
=QT_QPA_PLATFORMTHEME=kde=, Qt takes the cursor theme from KDE's =kcminputrc=
rather than from =$XCURSOR_THEME=, and falls back to Breeze when that file does
not name one. =~/.config/kcminputrc= therefore has to agree with the cursor
theme set in =hypr/theme.lua=.

imv only opens the paths it is handed. Passing a lone file would therefore give
a gallery of exactly one image, with nothing for =j= and =k= to move through.
Opening the *containing directory* and preselecting the file with =-n= is what
makes navigation walk the whole folder, which is the behaviour qimgv has by
default.

* gsr: GPU Screen Recorder profiles and replay control
:PROPERTIES:
:CUSTOM_ID: gsr
:header-args:shell: :tangle gsr :shebang #!/usr/bin/env sh
:END:

#+subtitle: One dispatcher for instant replay, regular recordings, and region capture

=gpu-screen-recorder= is driven by two separate mechanisms: long-lived
processes started with a full set of encoder flags, and Unix signals sent to
those processes to save or stop them. This script is the single entry point for
both, so the encoder settings live in exactly one place and the signal names
are never spelled out at a call site.

The name matters. Helper scripts named =gpu-screen-recorder-*= cannot signal
the recorder safely, because =pkill -f= matches against the whole command line
and a helper's own command line contains the pattern it is searching for. Such
a helper sends the signal to itself as well as to the recorder, and since the
default action for =SIGUSR1= is termination, it dies before it can report what
it did. Naming this script =gsr= removes the collision at its source.

** Prelude

=$0= is whatever name the caller used, so it is resolved through =PATH= and
made absolute. The recorder is told to run this same script as its post-save
hook, and that hook path must be absolute because the recorder's working
directory is not this script's.

#+begin_src shell
set -eu

self=$(realpath -- "$(command -v -- "$0")")
#+end_src

** Paths and process matching

#+begin_src shell
video_dir="${GSR_VIDEO_DIR:-$HOME/videos}"
token_dir="${XDG_CONFIG_HOME:-$HOME/.config}/gpu-screen-recorder"
recorder_pattern='(^|/)gpu-screen-recorder '
marker="${XDG_RUNTIME_DIR:-/tmp}/gsr-recording"
#+end_src

=$marker= records that a regular recording was started on top of a running
replay buffer. That is the one piece of state the recorder does not expose:
a buffer and a buffer-plus-recording look identical from the outside. It lives
in the runtime directory, which is tmpfs and cleared between logins, so a
marker cannot outlive the session that created it.

The trailing space in =recorder_pattern= is what makes it precise. Anchoring
with =^gpu-screen-recorder$= matches nothing at all, because =pkill -f= tests
the entire command line including arguments and a running recorder always has
some. The leading =(^|/)= keeps the pattern correct whether the recorder was
started by bare name or by absolute path.

Linux truncates process names to fifteen characters, so =gpu-screen-recorder=
is stored as =gpu-screen-reco= and =pkill -x= refuses the longer name outright.
Matching the full command line is the only option that works.

** Encoder settings

These flags apply to every profile. HEVC 10-bit is the best encoder this
hardware offers, since consumer Ampere has no AV1 encoder; the extra bit depth
mainly removes banding in gradients and sharpens small text. =-tune quality= is
NVIDIA-only and is off by default. Full color range preserves true black and
white levels, at the cost of clips looking washed out in players that assume
limited range.

#+begin_src shell
encode_flags='-k hevc_10bit -tune quality -cr full -ac opus -ab 192'
#+end_src

Where this variable and =$rate_flags= are used below they are left unquoted so
the shell splits them into separate arguments. Every value in them is a literal
without whitespace, so the split is exactly the intended one.

** Notifications and failure

The recorder reports its own saves through the =-sc= hook, so nothing here
announces a save optimistically. The one thing worth reporting eagerly is a
signal sent to a recorder that is not running, which is otherwise silent.

#+begin_src shell
notify() {
    notify-send -a gsr -u low -t 2000 "$@"
}

die() {
    printf 'gsr: %s\n' "$1" >&2
    exit 1
}

signal() {
    if ! pkill "-$1" -f "$recorder_pattern"; then
        notify 'No recorder running' 'gsr | nothing to signal'
        die 'no gpu-screen-recorder process found'
    fi
}
#+end_src

** Reporting state

The status bar polls this. Three states are reported: =idle= when no recorder
is running, =recording= while a regular recording or a region capture is being
written, and =buffer= while a replay buffer is armed but writing nothing.

A recorder started without =-r= is writing a file directly, so it is recording
whatever the marker says. The marker is removed whenever no recorder is running,
which is what keeps a stale one from surviving a recorder that crashed.

#+begin_src shell
status() {
    if ! pgrep -f "$recorder_pattern" >/dev/null 2>&1; then
        rm -f -- "$marker"
        printf 'idle\n'
    elif [ -e "$marker" ]; then
        printf 'recording\n'
    elif pgrep -f "$recorder_pattern.* -r " >/dev/null 2>&1; then
        printf 'buffer\n'
    else
        printf 'recording\n'
    fi
}
#+end_src

** Recording on top of a buffer

Toggling is the only operation the recorder offers here, so the marker is what
lets this report which direction it just toggled.

#+begin_src shell
record() {
    signal SIGRTMIN
    if [ -e "$marker" ]; then
        rm -f -- "$marker"
        notify 'Recording stopped' 'gsr | saving'
    else
        : > "$marker"
        notify 'Recording started' 'gsr | buffer still armed'
    fi
}
#+end_src

** Post-save hook

The recorder runs its =-sc= program with two arguments, the saved file's path
and one of =replay=, =regular=, or =screenshot=. It is executed directly rather
than through a shell, so the option cannot carry arguments of its own and this
script has to recognise the call by its shape: a first argument that is an
absolute path is the recorder calling back, never a subcommand.

#+begin_src shell
on_save() {
    notify "Saved | $2" "$(basename -- "$1")"
}
#+end_src

** Replay buffers

=start_replay= reads the profile variables set by =replay= immediately before
it is called.

#+begin_src shell
start_replay() {
    mkdir -p -- "$dir"
    notify 'Replay buffer started' "$profile | ${secs}s"
    exec gpu-screen-recorder \
        -w portal \
        -f 60 \
        -r "$secs" \
        -c "$container" \
        -a "$audio" \
        $encode_flags \
        $rate_flags \
        -df yes \
        -restore-portal-session yes \
        -restart-replay-on-save yes \
        -portal-session-token-filepath "$token_dir/$token" \
        -sc "$self" \
        -ro "$dir" \
        -o "$dir"
}
#+end_src

Each profile keeps its own portal restore token, which is what lets the buffer
restart without prompting for a screen-share target again.

The desktop profiles hold quality constant with =-bm qp=, which suits mostly
static content and keeps text clean. A one-second keyframe interval makes short
saved clips seek precisely, which matters when the useful part of a five-minute
buffer is a few seconds long. =-fm content= encodes only when the screen
actually changes; it is valid here because these profiles capture through the
portal, and has no effect on direct monitor capture under Wayland.

Games are high motion, where constant quality has no upper bound on size and
the buffer lives in RAM. Constant bitrate bounds it instead, at a rate chosen
to stay visually close to constant quality at this resolution while keeping an
hour of capture near twelve gigabytes rather than twenty. Constant frame rate
avoids the variable-frame-rate output that many editors mishandle, and Matroska
survives an interrupted write.

#+begin_src shell
replay() {
    case ${1:-desktop} in
        desktop)
            profile=desktop
            token=restore_token_desktop
            dir="$video_dir/replay-desktop"
            container=mp4
            audio=default_output
            rate_flags='-bm qp -q ultra -fm content -keyint 1'
            ;;
        secondary)
            profile=secondary
            token=restore_token_desktop_second_monitor
            dir="$video_dir/replay-desktop"
            container=mp4
            audio=default_output
            rate_flags='-bm qp -q ultra -fm content -keyint 1'
            ;;
        games)
            profile=games
            token=restore_token_games
            dir="$video_dir/replay-games"
            container=mkv
            audio=GameSink.monitor
            rate_flags='-bm cbr -q 30000 -fm cfr'
            ;;
        *)
            die "unknown replay profile: $1 (use desktop, secondary, or games)"
            ;;
    esac

    secs=${2:-300}
    start_replay
}
#+end_src

** Saving from the buffer

Each buffer length the recorder supports has its own real-time signal. A
cancelled save is reported by =signal=, and a successful one by the hook.

#+begin_src shell
save() {
    case ${1:-full} in
        full) signal SIGUSR1 ;;
        10)   signal SIGRTMIN+1 ;;
        30)   signal SIGRTMIN+2 ;;
        60)   signal SIGRTMIN+3 ;;
        300)  signal SIGRTMIN+4 ;;
        600)  signal SIGRTMIN+5 ;;
        1800) signal SIGRTMIN+6 ;;
        *)    die "unknown save length: $1 (use 10, 30, 60, 300, 600, or 1800)" ;;
    esac
}
#+end_src

** Region capture

=slurp= emits the recorder's own geometry format directly when given a format
string, so no reshaping of its output is needed. Cancelling the selection exits
quietly.

#+begin_src shell
region() {
    geometry=$(slurp -f '%wx%h+%x+%y') || exit 0
    [ -n "$geometry" ] || exit 0

    mkdir -p -- "$video_dir"
    exec gpu-screen-recorder \
        -w region \
        -region "$geometry" \
        -f 60 \
        -c mp4 \
        -a default_output \
        $encode_flags \
        -bm qp -q ultra \
        -fm cfr \
        -sc "$self" \
        -o "$video_dir/${1:-screen-rec-region}-$(now).mp4"
}
#+end_src

** Usage and dispatch

#+begin_src shell
usage() {
    cat <<'EOF'
usage: gsr <command> [arguments]

  replay [desktop|secondary|games] [seconds]   start a replay buffer (default: desktop, 300)
  save [10|30|60|300|600|1800]                 save from the buffer (default: the whole buffer)
  record                                       toggle a regular recording while a buffer runs
  stop                                         stop the buffer without saving
  region [name]                                select a region and record it
  status                                       print idle, buffer, or recording

Stopping a regular recording started with 'record' saves it; stopping a replay
buffer does not.
EOF
}
#+end_src

An absolute path in the first argument means the recorder is invoking this
script as its post-save hook, so that case is tested before any subcommand.

#+begin_src shell
case ${1:-} in
    /*)
        on_save "$@"
        ;;
    replay)
        shift
        replay "$@"
        ;;
    save)
        shift
        save "$@"
        ;;
    record)
        record
        ;;
    stop)
        signal SIGINT
        rm -f -- "$marker"
        notify 'Replay buffer stopped'
        ;;
    status)
        status
        ;;
    region)
        shift
        region "$@"
        ;;
    ''|-h|--help|help)
        usage
        ;;
    *)
        usage >&2
        die "unknown command: $1"
        ;;
esac
#+end_src
