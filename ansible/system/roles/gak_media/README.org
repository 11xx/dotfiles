#+TITLE: Shared media storage

This role owns the shared /media directory on the HDD.
Application roles own Compose projects and supporting configuration.
The media tree lives at /media/Media. Application state lives on the NVMe at
~/services/APPLICATION; applications own their mutable configuration and
directory permissions. Container-side mount paths stay stable across host
storage changes.

Selected configuration snapshots in the private vault are not complete
database or download-state backups. See [[file:../../GAK-SERVICES.org][service maintenance]].

* Users and groups

Application UID/GID values are container identities. Host file ownership
depends on the complete rootless UID/GID maps; matching numbers do not imply
matching identities. Inspect the maps and existing directory owners before
changing them. Shared media permissions must also work for NFS clients.

The media container maps swap intermediate IDs 0 and 1 and map the remaining
subordinate range identically. Container root retains intermediate ID 1;
application UID 1000 and GID 134 retain intermediate IDs 1000 and 134. Supplying
the complete range allows init processes to set application and supplementary
groups. With the host's subordinate range, application files appear as host
UID 100999 and GID 100133. This does not map the host's media group 134 into
the container; NFS access also depends on existing directory ownership and modes.

An =s6-applyuidgid= failure with =Invalid argument= can mean the requested
UID or supplementary group is absent from the container map. A container may
remain running while its application never starts. Check the HTTP endpoint,
not only =podman ps=. Test candidate maps with disposable containers and a
scratch bind mount before changing production ownership or mappings.

* Starting projects

The =gak-compose= Shepherd service starts only the explicit
=gak_compose_autostart= list. Podman restart policies supervise web containers;
there is no per-container Shepherd supervision. Explicit project stops remain
stopped until the lifecycle service or an operator starts them:

#+begin_src sh
sudo herd status gak-compose
podman compose -f ~/services/sonarr/compose.yaml up -d --pull never
podman compose -f ~/services/jellyfin/compose.yaml up -d --pull never
#+end_src

Recyclarr is a batch job, not a server: it syncs custom formats into Sonarr and
exits. It is deliberately absent from the autostart list. Run it when wanted:

#+begin_src sh
podman compose -f ~/services/recyclarr/compose.yaml run --rm recyclarr
#+end_src
