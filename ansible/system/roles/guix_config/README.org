#+TITLE: Gak Guix composition

This role owns the complete Gak system and Home expressions, channel list, and
host-specific values. The =ai_agent.remote.guix= and
=ai_agent.remote.gitolite= collection roles stage their separate concern
modules under ={{ guix_config_dir }}/modules/aiagent=. The system expression
imports each module only when its corresponding host selection is enabled.

Build the rendered expression after Ansible stages its inputs:

#+begin_src sh
guix system build -L ~/.config/guix/modules ~/.config/guix/system.scm
#+end_src

System activation remains an explicit operator action. Normal Ansible runs
deploy expressions and report pending activation; the =guix-activate= tag is
the only privileged path. See the =ai-agent-remote= architecture and operations
documents for module runtime invariants, backup recovery, Gitolite policy, and
the collection role interfaces.

Guix Home owns Gak's zsh startup entry and loads
=~/.config/zsh/local.zsh= from the user's shell configuration. The file must
exist before =guix home reconfigure ~/.config/guix-home/home-configuration.scm=.
The expression provides zsh, atuin, and zoxide; the user's file owns bindings
and shell behavior.

The host-specific operator runtime probe exercises the rendered
=gak-operator-runtime= program against disposable local paths. On Gak, use the
current expression and the module files staged by the collection roles:

#+begin_src sh
python3 tests/gak/gak-operator-runtime.py \
  ~/.config/guix/system.scm ~/.config/guix/modules
#+end_src

Namespace scratch is removed by the probe. It does not start or stop a service
or apply a Guix generation.
