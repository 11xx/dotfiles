* Harness notes

This role builds one persistent rootless Podman container for terminal-first AI
coding harnesses. The isolation boundary is the container plus Codex/OpenCode/Pi
permissions; the host only shares =/home/work= and the explicitly mounted state
directories.

- =opencode= is a terminal coding agent with its own config/state.
- =codex= is OpenAI's terminal coding agent. In this container it edits and runs
  commands against the mounted =/workspace= tree, not the host filesystem in
  general. Codex still has its own sandbox/approval layer; the wrapper
  =codex-auto= starts it in workspace-write/on-request mode.
- =pi= is the minimal terminal harness. Its own philosophy is closer to "bring
  your own workflow" than OpenCode's batteries-included approach, so the
  container is the main safety boundary. The =pi-readonly= wrapper is useful
  for audits.
- =codex-auto=, =t3-web=, and =pi-readonly= are container-internal wrappers
  installed into =/home/node/.bin=. They are not host commands by themselves.
  Host shell functions below call them through =machinectl= and =podman exec=.
- T3 should run inside the existing harness container, not as a separate
  sidecar container. It wraps =codex app-server=, so running it in the same
  container gives it the same Codex binary, OAuth state under =~/.codex=, and
  mounted =/workspace= view as terminal Codex.
- A small user =t3-web.service= is the clean background-start option for T3.
  Quadlet is still the right layer for the long-lived container itself, but a
  regular systemd service is a better fit for a foreground process started with
  =podman exec= inside that container.
- The base image is pinned to Fedora 44. Quay's =quay.io/fedora/fedora= image
  is the normal Fedora container base; keep the release pin rather than using
  =latest= so rebuilds are predictable.

#+begin_src shell :tangle (tdir "opencode/init.sh") :shebang #!/usr/bin/env bash :tangle-mode o750
set -euo pipefail

INIT_DIR="${HOME}/init.d"

if [[ -d "$INIT_DIR" ]]; then
  shopt -s nullglob
  for f in "$INIT_DIR"/*; do
    [[ -f "$f" && -x "$f" ]] || continue
    "$f"
  done
  shopt -u nullglob
fi

echo 'END init.sh, running provided CMD'

- GHCUp bootstrap ::
#+begin_src shell :tangle (tdir "init.d/haskell-bootstrap.sh") :shebang #!/usr/bin/env bash :tangle-mode o750
set -euo pipefail

GHCUP_BIN="$HOME/.ghcup/bin/ghcup"

if [[ ! -x "$GHCUP_BIN" ]]; then
    echo "[init] Bootstrapping Haskell toolchain..."

    # see options https://github.com/haskell/ghcup-hs/blob/master/scripts/bootstrap/bootstrap-haskell
    export BOOTSTRAP_HASKELL_NONINTERACTIVE=1   # suppress all prompts
    export BOOTSTRAP_HASKELL_INSTALL_HLS=1      # HLS is opt-in even in noninteractive
    export BOOTSTRAP_HASKELL_INSTALL_NO_STACK=1 # omit Stack
    export BOOTSTRAP_HASKELL_STACK_SETUP=1      # stack/ghcup integration
    export BOOTSTRAP_HASKELL_GHC_VERSION=recommended
    export BOOTSTRAP_HASKELL_CABAL_VERSION=recommended
    # BOOTSTRAP_HASKELL_ADJUST_BASHRC must be UNSET (not empty) to suppress
    # .bashrc modification in noninteractive mode — unset is the default
    unset BOOTSTRAP_HASKELL_ADJUST_BASHRC

    curl --proto '=https' --tlsv1.2 -sSf https://get-ghcup.haskell.org | sh

    if [[ -f "$HOME/.ghcup/env" ]]; then
        . "$HOME/.ghcup/env"
    fi

    cabal update --ignore-project
    echo "[init] Haskell toolchain ready."
else
    if [[ -f "$HOME/.ghcup/env" ]]; then
        . "$HOME/.ghcup/env"
    fi

    cabal update --ignore-project
    echo "[init] Haskell toolchain already present, skipping."
fi
#+end_src

  "Return SEARXNG_PORT value from the .env file as a string."
