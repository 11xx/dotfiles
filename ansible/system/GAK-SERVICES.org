#+TITLE: Gak service maintenance
#+options: toc:nil num:nil

* Ownership

Each =roles/gak_APPLICATION= owns its =templates/compose.yaml.j2=, image
channel, configuration tasks, secret files and operating instructions.
Nextcloud owns its database, cache, cron and backup schedule as one Compose
project. The resulting files live at =~/services/APPLICATION/compose.yaml= and
are owned by the login user.

=host_vars/gak/main= selects =gak_applications= and the explicit
=gak_compose_autostart= list. It also supplies =gak_compose_supported=,
=gak_compose_never_autostart= and =gak_compose_external_networks=. The
autostart list may select declared web applications and Nextcloud, but never
the Recyclarr batch job. The =ai_agent.remote.compose_runtime= collection role deploys the five
instance lists, shared lifecycle helper and updater package sources under the
login user's home. Guix Home installs the update command from those sources.
The
lifecycle helper requires =.compose-supported=, =.compose-applications=,
=.compose-autostart=, =.compose-never-autostart= and =.compose-networks= in
the services root. Every file uses one name per line and may be empty.
Entries must be unique and valid names. A
declared project's =compose.yaml= must exist. A project with dependent
services declares =.compose-stop-order= beside its Compose file, with one
Compose service name per line in shutdown order. The helper refuses malformed
or missing instance data and does not discover boot projects from a directory
listing. Boot selection and update selection are separate questions: the update
command discovers projects from the services root and never consults the
instance lists.

Ansible owns service directories, Compose files, operator commands and secret
files. Guix System owns only stable host integration: rootless Podman,
subordinate ID ranges, linger/cgroup prerequisites, filesystem and networking
requirements, mcron and one Shepherd service. Guix Home owns the login user's
tooling, including the Compose provider and the interpreter its YAML support
runs on. Tailscale owns ingress.

* Agent host instance

The =gak-aiagent= inventory target keeps its own =aiagent= account and mounted
home. The =ai_agent.remote.agent= role installs the workload, while
=ai_agent.remote.operator= installs the existing workstation command at
=~/.local/bin/gak-aiagent=. The agent and media instances install the same
=compose_runtime= role into their separate accounts.

The =gak_aiagent_host_enabled= and =gak_git_hub_enabled= selections control
whether the host and Gitolite Guix modules are staged and imported. The full
system composition remains here; the collection owns those concern modules
and their package tests. Build the rendered system expression before the
explicit activation step. The workload's operator commands, provider state,
update boundary, root backup, Gitolite policy and recovery procedures are
maintained in =ai-agent-remote/docs/operations.org= and
=ai-agent-remote/docs/architecture.org=.

The first host retains the existing =/home/aiagent= image-backed account,
container-home, workspaces, cache, rootless Podman maps, loopback T3 port and
image channel. An extraction apply does not update providers, copy mutable
state, or start or stop the running project.

* Storage and namespaces

=/media= is the HDD mount and holds =/media/Media=. Application state lives on
the NVMe under =~/services/APPLICATION=: media applications use a =config=
subdirectory, Jellyfin also uses =cache=, and Recyclarr uses its application
directory directly. Container-side =/config=, =/cache= and =/Media= paths stay
stable. No data is moved by the Compose cutover.

The media containers use the complete rootless map:

#+begin_example
--uidmap 0:1:1 --uidmap 1:0:1 --uidmap 2:2:65535
--gidmap 0:1:1 --gidmap 1:0:1 --gidmap 2:2:65535
#+end_example

This keeps the LinuxServer and Hotio application identity at container
1000:134, which appears on the host as the mapped ownership already used by
the state and media tree. Jellyfin retains the same full root map without
PUID/PGID variables. Recyclarr retains its default rootless namespace and
runs as container 1000:134; its secret file remains mode 0640 with the mapped
group ownership. Nextcloud keeps its tested namespace-aware secret and
database ownership operations.

The media instance declares =starrs_net=, =services_net= and =nextcloud_net=
as external networks. The login-user lifecycle helper creates them when a selected
stack needs them. Every Compose file declares its network as external, so a
project's =compose down= cannot remove a shared network. Compose projects do
not share application state or networks across those boundaries.

* Boot and ordinary operations

The host composition retains the stable Shepherd service =gak-compose=.
=ai_agent.remote.compose_runtime= deploys its lifecycle helper and
Compose policy lists; system.scm selects the existing operator user,
PATH, mount and cgroup prerequisites. Boot selection remains an explicit list.
Recyclarr is never in that list, and an empty list starts no projects.

Inspect the integration and containers as follows:

#+begin_src sh
sudo herd status gak-compose
podman ps -a
podman network ls
podman logs CONTAINER
#+end_src

Run an individual media project with the ordinary Compose interface:

#+begin_src sh
podman compose -f ~/services/sonarr/compose.yaml pull
podman compose -f ~/services/sonarr/compose.yaml up -d --force-recreate --pull never
podman compose -f ~/services/recyclarr/compose.yaml run --rm recyclarr
#+end_src

The media projects keep their current networks and state paths. The shared
helper's ownership, shutdown and crash-recovery invariants are maintained in
=ai-agent-remote/docs/architecture.org=.

* Updating images

The packaged =gak-services= command uses the Compose files under =~/services=
as service truth. The shared updater validates projects before pulls, selects
only running projects for =--all=, preserves stopped projects, and applies
updates one project at a time. Run:

#+begin_src sh
gak-services list
gak-services update --all --dry-run
gak-services update --all
gak-services update sonarr jellyfin
#+end_src

The command's process bounds, readiness contract, diagnostics and recovery
limits are documented in =ai-agent-remote/docs/operations.org=. Media image
channels and project-specific update hooks remain in each application role.
Nextcloud's existing backup command remains its =before-update= gate, and its
readiness command still requires a healthy application status response.

* Deployment and activation

Run from this directory:

#+begin_src sh
AI_AGENT_REMOTE_COLLECTION_SOURCE=/path/to/ai-agent-remote \
  ./bin/install-remote-collection
#+end_src

=AI_AGENT_REMOTE_COLLECTION_SOURCE= names a local Git repository containing
the full commit in =collection-pin=. The installer archives that commit's
=ansible/= subtree into temporary =$HOME/.cache= scratch before building. The
repository's checked-out HEAD and mutable worktree files do not affect the
artifact, and the source repository is not modified or fetched from a remote.

Before removing the tracked workstation command during the live cutover, let
the new operator role install it at the same path:

#+begin_src sh
ansible-playbook -i localhost, gak.yaml --limit localhost --tags gak-aiagent-operator
#+end_src

The ordinary =hosts= inventory has no =localhost= entry. The standalone
host-list inventory targets the controller play without adding localhost to
the remote inventory. Preview the selected operator task without executing
it with:

#+begin_src sh
ansible-playbook -i localhost, gak.yaml --limit localhost \
  --tags gak-aiagent-operator --list-tasks
#+end_src

Compare the installed command with the collection artifact before integrating
the source deletion. The new command keeps the =gak-aiagent= path and interface.

Then validate and deploy the reviewed collection roles:

#+begin_src sh
ansible-playbook gak.yaml --syntax-check
ansible-playbook gak.yaml --tags guix,gak-media,gak-services,gak-compose --check
ansible-playbook gak.yaml --tags guix,gak-media,gak-services,gak-compose
#+end_src

Portable updater and lifecycle suites live with the collection. Consumer
fixtures render the installed collection through the Gak media roles and
validate host-specific selections:

#+begin_src sh
python3 tests/gak/list-render.py
tests/gak/autostart-validation.bash
tests/gak/nextcloud-extension.bash
tests/gak/nextcloud-readiness.bash
python3 tests/gak/t3-port-render.py
python3 tests/gak/module-selection.py
python3 tests/gak/compose-consumer-check.py
#+end_src

Exercise the pinned artifact bootstrap with a disposable source clone:

#+begin_src sh
AI_AGENT_REMOTE_COLLECTION_SOURCE=/path/to/ai-agent-remote \
  python3 tests/gak/collection-bootstrap.py
#+end_src

Set =AI_AGENT_REMOTE_COLLECTION_ROOT= to the installed collection root for
these commands. =TMPDIR= should point to task-owned scratch under the user's
home.

A fixture that needs a tool the machine lacks exits 77 and says so.

Applying the Home environment is unprivileged and separate from the system
generation. Ansible ships the declaration and never applies it:

#+begin_src sh
guix home reconfigure ~/.config/guix-home/home-configuration.scm
#+end_src

Run it after Ansible deploys the declaration and before the update command is
first used, because that is what puts the Compose provider on PATH. Start a new
login shell afterwards so the profile's search paths are exported. The command
itself needs no reconfiguration for an image update; only a change to the
declared tooling does.

Application deployments and enabled-list edits are unprivileged. When the
Guix host integration itself changes, the play reports the pending activation.
Review the rendered expression, then opt in explicitly:

#+begin_src sh
umask 022
ansible-playbook gak.yaml --tags guix-activate \
  -e gak_activate_system=true
#+end_src

For a first cutover, include the deployment tags before the activation tag so
the post-task runs after the Compose files, lists, helper and Guix expression
are deployed:

#+begin_src sh
ansible-playbook gak.yaml \
  --tags guix,gak-media,gak-services,gak-compose,guix-activate \
  -e gak_activate_system=true
#+end_src

The activation task is skipped in check mode and is the only task in this play
that uses privilege escalation. A host reconfiguration is not needed for a
Compose image pull or for a change to =gak_compose_autostart=.

Build and inspect the generated system expression before activation:

#+begin_src sh
guix system build -L ~/.config/guix/modules ~/.config/guix/system.scm
sudo herd status gak-compose
podman ps -a
#+end_src

Building Guix programs does not execute their root-only paths. Portable module
probes live in =ai-agent-remote/tests/guix= and use disposable targets. The
Gak-specific operator runtime test remains in =tests/gak=:

#+begin_src sh
python3 tests/gak/gak-operator-runtime.py \
  ~/.config/guix/system.scm ~/.config/guix/modules
#+end_src

It uses =podman unshare= for Guile privilege-drop calls and does not activate a
Guix generation.

Use =umask 022= for activation so generated host files remain readable by
unprivileged services. A backup process's restrictive umask must not carry
into reconfiguration. Check that =lobo= can read =/etc/hosts= afterwards.

* Image channels and rollback references

The source names publisher-supported moving channels rather than deployment
digests:

| project | image channel |
|---------+---------------|
| sabnzbd | =lscr.io/linuxserver/sabnzbd:latest= |
| prowlarr | =lscr.io/linuxserver/prowlarr:latest= |
| sonarr | =ghcr.io/hotio/sonarr:latest= |
| radarr | =ghcr.io/hotio/radarr:latest= |
| jellyfin | =docker.io/jellyfin/jellyfin:latest= |
| qbittorrent | =lscr.io/linuxserver/qbittorrent:latest= |
| recyclarr | =ghcr.io/recyclarr/recyclarr:8= |
| koito | =gabehf/koito:latest= |
| nextcloud | =docker.io/library/nextcloud:34-apache= |
| PostgreSQL | =docker.io/library/postgres:17-alpine= |
| Redis | =docker.io/library/redis:8.2-alpine= |

Before the first Compose recreation, the operator records the running image
IDs and tags each existing image with the corresponding alias. This seeds the
aliases without pulling or changing software. Keep the observed IDs and the
last working Compose files as the rollback record; do not put those digests in
the Guix expression. A later update is explicit: =gak-services update= pulls the
declared channel, recreates the project and reports the before and after image
IDs. Run the application's native version and caller-visible checks afterwards,
and retain the previous image until they pass. Advancing the Nextcloud major,
the PostgreSQL major or the Redis 8.2 series is a deliberate edit to the role
defaults, never a side effect of an update run.

* One-time ownership handover

The old generation's OCI services must be quiet before Compose creates the
same stable names. Save the old generated configuration before activation, and
separate long-running services from the manual batch job. On Gak, with the
current generation still running:

#+begin_src sh
cp --reflink=auto ~/.config/guix/system.scm ~/.config/guix/system.scm.before-compose
old_web_services=(sabnzbd prowlarr sonarr radarr jellyfin qbittorrent koito)
old_nextcloud_frontend=(nextcloud-cron nextcloud)
old_nextcloud_backend=(nextcloud-redis nextcloud-db)
old_batch_services=(recyclarr)
for service in "${old_web_services[@]}" "${old_nextcloud_frontend[@]}" \
               "${old_nextcloud_backend[@]}" "${old_batch_services[@]}"; do
    sudo herd disable "$service"
done

for container in "${old_web_services[@]}" "${old_nextcloud_frontend[@]}" \
                 "${old_nextcloud_backend[@]}"; do
    if podman container exists "$container"; then
        podman stop --time 30 "$container"
        while :; do
            if podman container exists "$container"; then
                sleep 1
            else
                exists_status=$?
                [[ $exists_status == 1 ]] || exit "$exists_status"
                break
            fi
        done
    fi
done
podman ps -a --format '{{.Names}}|{{.Status}}'
#+end_src

The loop checks both graceful exit and the asynchronous removal race. Confirm
the state directories, secrets, media mount and image IDs before activating
the generation containing =gak-compose=. Start =gak-compose= and inspect its
recorded projects, container names, networks, ports and mounts. No project
should be started merely because its directory exists.

If startup fails, stop the recorded Compose projects and preserve the error
and state file. For a rollback, stop and disable =gak-compose=, explicitly
reconfigure the retained old generated configuration, re-enable only the old
web services and wait for their containers to settle before starting them:

#+begin_src sh
old_web_services=(sabnzbd prowlarr sonarr radarr jellyfin qbittorrent koito)
old_nextcloud_frontend=(nextcloud nextcloud-cron)
old_nextcloud_backend=(nextcloud-db nextcloud-redis)
sudo herd stop gak-compose
sudo herd disable gak-compose
sudo guix system reconfigure -L ~/.config/guix/modules ~/.config/guix/system.scm.before-compose
for service in "${old_web_services[@]}" "${old_nextcloud_backend[@]}" \
               "${old_nextcloud_frontend[@]}"; do
    sudo herd enable "$service"
done
for service in "${old_web_services[@]}" "${old_nextcloud_backend[@]}" \
               "${old_nextcloud_frontend[@]}"; do
    sudo herd start "$service"
done
#+end_src

The state paths do not change, so a rollback does not move or copy data.
The manual Recyclarr batch service is not started by the rollback. Recheck
application health and the Nextcloud backup/restore path after either direction.

* Updates and recovery

Record the running image and application version, read upstream migration
requirements, and make a consistent backup before changing an image channel.
Media applications need stopped or application-consistent copies of complete
state, including databases and torrent resume metadata. Selected configuration
files in private Git are not a complete restore. A backup target should be on
a different physical disk; document whether an off-host copy exists.

Nextcloud's mcron job runs =~/.local/bin/gak-nextcloud-backup= as =lobo=. It
uses maintenance mode, a native PostgreSQL dump, the complete =html= tree,
encrypted Restic storage at =/marak/backups/nextcloud/restic=, retention and a
repository check. Its zero exit means a fresh complete snapshot with the
instance out of maintenance mode and nothing else: contention exits 75 and a
maintenance mode that could not be cleared fails the run. The Nextcloud Compose
project names it as its =before-update= gate, so an update of that project
either snapshots first or recreates nothing.

=gak-nextcloud-restore-check= uses the image identity of the running
=nextcloud-db= container for its isolated scratch database, validates real
application tables and removes only its own scratch state.

Agent image updates, provider state, root backup and rollback are documented
in =ai-agent-remote/docs/operations.org=. The host's private password,
repository location, retention values and mutable backup state remain in the
Gak configuration and on the host.

Removing an application from =gak_applications= controls role execution and
the generated declared list. It does not erase state, remove a network or
revoke an existing Tailscale endpoint. Drain ingress, stop the selected
project and retain a verified backup before separate removal.

* Agent Git exchange

The =agentgit= account, its private key and repository data remain host-owned.
The collection provides the Guix module, root-safe receive trigger and policy
skeleton; the host expression selects Gitolite independently from the agent
workload. The policy grants the operator administrative control and confines
agent writes to its work branches. The shared backup lock keeps Gitolite
receives and repository bundles mutually exclusive. Setup, push, backup and
restore commands are documented in =ai-agent-remote/docs/operations.org=.
