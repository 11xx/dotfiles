#+TITLE: Household systems, declared
#+options: toc:nil num:nil

Ansible for the three machines that make up the household: a desktop, a home
server, and the Pi that answers DNS for both.

This tree owns machine inventories, host compositions, media application roles,
and host-specific selections. Plain files and templates are maintained directly;
Org documents describe operational boundaries.

The =ai-agent-remote= project owns the portable agent workload, workstation
operator command, shared Compose runtime and Guix/Gitolite concern modules.
This tree selects the =ai_agent.remote= roles and retains host-specific
inventory, media declarations, whole-system composition, storage and ingress.
Build and install the collection with =bin/install-remote-collection= before
running a play that imports it.

* The machines

| ~ak~  | Arch desktop. Managed locally, by the playbook running on it.       |
| ~gak~ | Guix System home server. NFS for the media trees, rootless podman.  |
| ~pak~ | Raspberry Pi on Debian. Pi-hole, unbound, caddy, vaultwarden.       |

Hosts are grouped twice over: by distribution, which decides what a role has to
speak, and by purpose, which decides what it should do. A shell role asks the
first for the package names and the second for whether to install anything that
needs a display.

* Running it

Each machine has its own playbook, and one more runs all three. Always with
=--check --diff= first — every role here can take a working machine down.

#+begin_src sh
ansible-playbook site.yaml --check --diff
ansible-playbook system.yaml --tags firewall --check --diff
#+end_src

Tags come in two levels. Every role answers to its own name, and roles that do
several separable things also tag those individually, so a shell plugin bump
does not reinstall fonts. =--list-tags= prints the current set.

* Two things worth knowing before changing anything

** Guix is normally shipped, explicitly applied when requested

Ansible normally writes gak's Scheme configuration and stops there. Guix
already knows how to turn those files into a running system, a reconfigure is
slow enough to want a human watching it, and a bad expression can leave the
host unbootable. The explicit default-off =guix-activate= post-task may apply
the reviewed configuration after all Ansible-owned files are deployed; normal
application and Compose-list changes remain unprivileged.

Guix System ships no Python, so gak needs one installed by hand before Ansible
can reach it at all. After that its own configuration keeps the interpreter
alive.

** The shell is shared, once

All three machines source the same numbered fragments, deployed from one place.
Anything host-specific stays out of them and is sourced afterwards, where it can
override whatever it needs to. The desktop's large interactive config is layered
on top this way rather than being duplicated or trimmed down.

zsh plugins are pinned checkouts rather than distribution packages: the two
package managers disagree on names, paths and what they even carry, and a
checkout at a tag puts identical files in identical places. Guix cannot use that
layout — it has no =/usr/share= — so it builds the same plugins at the same
versions from a local channel into the same relative paths.

* Secrets

Vaulted values are network facts and credentials — anything describing the
private network rather than the machines. Everything else is deliberately in the
open, because this repository is public.
