#+TITLE: Systemd environment variables
#+PROPERTY: header-args :mkdirp yes

Systemd don't share environment variables with the login shell, for them to
be available to services declarations need to be done in
the ~$XDG_CONFIG_HOME/environment.d/*.conf~ files.

*Files should end with the ~.conf~ extension.*

- See
  + [[https://www.baeldung.com/linux/systemd-services-environment-variables][Setting Environment Variables for systemd Services | Baeldung on Linux]]
  + [[https://curiouscoding.nl/linux/environment-variables/][Environment variables done once · CuriousCoding]]
    # [2023-02-24 Fri 14:39:55 -03]

The following set variables and script generators shall be used with
: /usr/lib/systemd/user-environment-generators/30-systemd-environment-d-generator
to print the variables to a shell, for example.

* 20-xdg.conf: XDG Base Directory
:PROPERTIES:
:header-args:conf: :tangle "20-xdg.conf"
:END:

For the XDG standard, =XDG_STATE_HOME= is less conventional, and
=XDG_BIN_HOME= is /not/ a part of the specification but commonly used.

#+begin_seealso
- [[https://specifications.freedesktop.org/basedir-spec/basedir-spec-latest.html][XDG Base Directory Specification]]
- [[https://stackoverflow.com/questions/25897836/where-should-i-write-a-user-specific-log-file-to-and-be-xdg-base-directory-comp/27965014#27965014][Where should I write a user specific log file to (and be XDG base directory compatible) - Stack Overflow]]
#+end_seealso

#+begin_src conf
XDG_DATA_HOME=$HOME/.local/share
XDG_CACHE_HOME=$HOME/.local/cache
XDG_CONFIG_HOME=$HOME/.config
XDG_STATE_HOME=$HOME/.local/state
XDG_BIN_HOME=$HOME/.local/bin
PATH=${PATH}:${XDG_BIN_HOME}
#+end_src
