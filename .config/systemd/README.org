** Claude window ping timer
This timer sends Claude a minimal =hi= prompt every five hours so its
subscription window is active before an interactive session needs it.  The
invocation pins Haiku, low effort, and non-persistent sessions; slash commands
are disabled because the ping never needs tools or skills.  Claude is the only
enabled instance.

*** helper script
#+begin_src bash :tangle (concat (xdg-bin-home) "/ai/ai-window-ping") :shebang "#!/usr/bin/env bash" :tangle-mode o755
set -u

PATH="${PATH:-/usr/local/bin:/usr/bin}:${HOME}/.local/bin:${HOME}/.local/bin/ai:${HOME}/.local/share/npm/bin"

prompt="hi"
claude_model="haiku"
claude_effort="low"
timeout_duration="${AI_WINDOW_PING_TIMEOUT:-180s}"
state_dir="${XDG_STATE_HOME:-${HOME}/.local/state}/ai-window-ping"

mkdir -p "$state_dir"

log() {
    printf '[%s] %s\n' "$(date '+%Y-%m-%dT%H:%M:%S%z')" "$*"
}

run_claude() {
    timeout "$timeout_duration" \
        claude -p \
        --model "$claude_model" \
        --effort "$claude_effort" \
        --disable-slash-commands \
        --no-session-persistence \
        "$prompt"
}

if (( $# > 0 )) && [[ "$1" != claude || $# -gt 1 ]]; then
    log "ERROR: only the Claude instance is supported"
    exit 64
fi

output_log="$(mktemp "${TMPDIR:-/tmp}/ai-window-ping.claude.XXXXXX")"
log "Pinging Claude..."
if run_claude >"$output_log" 2>&1; then
    date '+%Y-%m-%dT%H:%M:%S%z' > "${state_dir}/claude.last-success"
    log "Claude ping succeeded."
else
    rc=$?
    log "ERROR: Claude ping failed with exit status ${rc}."
    sed -n '1,80p' "$output_log" >&2
    rm -f "$output_log"
    exit "$rc"
fi
rm -f "$output_log"

exit 0
#+end_src

*** service template
:PROPERTIES:
:header-args:systemd: :tangle (concat (xdg-config-home) "/systemd/user/ai-window-ping@.service")
:END:

#+begin_src systemd
[Unit]
Description=Ping %i to start its five-hour usage window
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
TimeoutStartSec=6min
ExecStart=%h/.local/bin/ai/ai-window-ping %i

[Install]
WantedBy=default.target
#+end_src

** Manually create and drop-in override for Systemd service
- In the services directory =/etc/systemd/system/=, for system-wide
  services, or =${XDG_CONFIG_HOME}/systemd/user= for user services;
- create a directory with the same name as the service to be overridden
  but with a =.d= added to the end, e.g. =my-app.service.d=
- inside the =my-app.service.d= create a file with the =.conf= extension
  containing the override changes, like would be done with =systemctl edit=.
  The name =override.conf= is recommended.
- After changes reload the daemon: =systemctl daemon-reload=
- Restarting the service after reloading the daemon may be necessary:
  : systemctl restart my-app.service
- And to revert changes simply delete the =my-app.service.d= directory.

** Scripts in Exec not found

Arch Linux respects =usr/loca/bin= so using that for personal scripts is
the most supported way without customizing systemd's PATH, that is
separate from the login shell one.

** Use of empty =ExecStart==
[[https://stackoverflow.com/questions/68817332/why-use-execstart-with-no-value-before-another-execstart-new-value-in-a-syst/68818218#68818218][Why use ExecStart= (with no value) before another ExecStart=/new/value in a systemd override? - Stack Overflow]]
# [2023-09-11 Mon 01:30:30 -03]
When using an =override.conf= setting =ExecStart== for a service file that
already contains a =ExecStart==, the following error may be given:
#+begin_example
Failed to start servicename.service: Unit servicename.service has a bad unit file setting.
See user logs and 'systemctl --user status servicename.service' for details.
#+end_example
so an empty =ExecStart== before the override e.g. =ExecStart=command= is
to clear any conflicts since systemd only allows one ExecStart.
